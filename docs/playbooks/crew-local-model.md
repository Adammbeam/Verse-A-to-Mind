# A crew agent on a free local model (Ollama)

**Starts when:** a crew seat or an owner-side machine has no paid model key but has Ollama running on the same machine. The same coder and the same jobs run against a local model; a-to-mind.com keeps answering from its own cloud path with the switch off.

Source: `https://github.com/ollama/ollama`, MIT. The copyright and permission notice are kept in the repository's credits data (`void-live-deploy/salvage.json`, generated by `node tools/autosalvage/unify.mjs --write`) and published on `/credits/`. No Ollama source is copied into Verse.

## What starts it

A person runs Ollama on their own machine and sets `OLLAMA_MODEL` for the agent process. Nothing in Cloudflare Workers, the browser or the default `tools/verse-coder.mjs` stack starts or needs it.

## Commands

```
# on the agent's own machine, once
ollama serve
ollama pull qwen3:4b

# point Verse's coder at the local model; no key is read or sent
OLLAMA_MODEL=qwen3:4b node tools/verse-coder.mjs --task "Say hello in one sentence"

# a team seat in a tool shell keeps the same setting for the jobs it works
OLLAMA_MODEL=qwen3:4b node agent.mjs next --wait

# never let a prompt leave the machine, even if cloud keys are present
OLLAMA_MODEL=qwen3:4b VERSE_CODER_OLLAMA_ONLY=1 node tools/verse-coder.mjs --task "..."
```

`OLLAMA_BASE` defaults to `http://127.0.0.1:11434` and is refused unless it is a local address (`localhost`, `127.0.0.1` or `[::1]`). With `OLLAMA_MODEL` set, the coder probes `/api/tags` first and then posts one chat-completion request to `/v1/chat/completions`; with no model set, that provider is never added and the existing free stack is byte-for-byte the same. A local server that is down is a clean fall-through, not a production failure.

## How to tell it worked

`node --test --test-name-pattern="opt-in local Ollama" tools/verse-coder.test.mjs` passes: the provider appears only when asked, the probe and the completion both go to localhost, a down server yields `no model answered (ollama not running)`, and the cloud-only stack stays unchanged. On a machine with Ollama, the task above prints a model answer and no key is named. With Ollama off, the ordinary site ask still gets the server's answer: the site route never reads these variables.

## Mistakes made

- Treating a local model as a new default. It is opt-in: the site and its workers must never depend on the binary.
- Pointing `OLLAMA_BASE` at a remote host. That is refused, so a local job cannot quietly phone home.
- Assuming a small model can drive every coding job. Check tool calls and the coder's caps; `docs/playbooks/openhands.md` records what a 4B model could and could not do on this box.
